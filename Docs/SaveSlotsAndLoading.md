# 存档与启动优化

- 启动先显示三个独立存档位，选择后进入游戏；第一个存档兼容原 farm-v1.json 与 .bak。
- 游戏内 F5 打开独立存档菜单，暂停时间与模拟；可返回、切换存档、选择空位新建。
- 重新开始有二次确认：原主文件和备份复制到 persistentDataPath/Archives/时间戳，再写入全新世界。新世界第1天，金币/木材/石料各1000。
- 切换前强制保存，保存失败保留当前旅程。旧场景卸载时禁止再次保存，防止覆盖重开后的文件。
- 加载前先呈现提示，世界尚未初始化时不接受游戏输入。不使用虚假的百分比进度。
- 矿洞内部延迟到首次进入时生成；地下存档继续游戏时仍恢复内部与位置。
- 普通存档请求合并为2秒一次，暂停应用、退出、切换时立即写盘；失败延迟10秒再试。意外终止最多可能丢失合并窗口内的改动。
- 附近资源/遭遇扫描从每帧改为10Hz；E交互即时重新扫描，砍树与采矿也保留即时校验。

验证：Unity编译通过；一次Play验证启动菜单、原第31天存档继续、菜单暂停、单一EventSystem、矿洞按需生成、新建第3槽及场景切换、初始资源。验证结束恢复原存档及备份。未运行完整测试套件，未测量启动耗时或帧率提升百分比。
