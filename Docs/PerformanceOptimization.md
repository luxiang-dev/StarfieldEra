# 地形与村民 CPU 优化（2026-10-17）

本次优化运行时计算和临时对象，未降低地图分辨率、模型精度或画质。

## 改动

- 干燥地面查询不再遍历全部水域寻找水位；水岸仍使用原有水位与混合规则。
- 地形重建复用已有采样，每个网格顶点只计算一次水岸距离；三角形裁切复用一个缓冲区，完全干燥的三角形直接跳过。预先分配地面网格列表容量，移除逐三角形创建的数组。
- 移动检测缓存地形与游戏组件、十二个脚边采样方向，零位移提前返回。寻找安全落脚点时先比较平面距离，再计算候选高度。
- 村民移动复用避障角度数组，工作地点查找不再创建捕获闭包，回家不再逐人逐帧生成房屋列表。积水网格移除逐三角形的临时数组。

## 本机验证

Unity 6000.3.26f1 Editor Play 模式，同一个第 31 天存档、同一地形；高度查询先预热。以下是本次单次采样，含编辑器环境波动，不能直接换算为游戏 FPS。

| 项目 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 完整地形、水面与碰撞体重建 | 1221.63 ms | 605.94 ms |
| 3000 次分布式地形高度查询 | 20.57 ms | 16.16 ms |
| 1000 次分布式可站立检测 | 16.75 ms | 13.82 ms |

重建耗时约降低 50%。使用随附检测脚本再次验证，优化后重建为 505.52 ms，高度查询 14.95 ms，可站立检测 12.19 ms，二进制摘要仍相同。当前运行环境的 `GC.GetAllocatedBytesForCurrentThread()` 始终返回零，因此不据此报告 GC 字节数；临时数组与闭包的减少来自代码路径检查。

对 23,265 个位置的高度和水岸可行走结果，以及地面、水面全部顶点、顶点颜色与三角形索引进行二进制比较，改动前后完全相同：SHA-256 `6e14589beb64ade2fa4456cfb6ac1cceb8857bada3afbfdf36550e4ba9cb9874`。地面 67,721 顶点、403,200 索引；水面 4,030 顶点、4,584 索引。

运行时另验证实际建房、招募第 4 位村民、装饰放置回收和雷暴过夜（1,544 处积水）；状态与保存均有效。测试结束后恢复玩家原始存档及其备份。

## 复测

`Tools/Performance/TerrainProbe.cs` 是 Unity CLI eval_file 片段，不属于游戏构建。备份存档，进入 Play 并等待世界初始化后，在项目目录运行：

```bash
unity command eval_file --caller plugin --skill unity-cli --file Tools/Performance/TerrainProbe.cs --format json
```

输出在 `Temp/TerrainPerformance/`：`queries.txt`、延迟完成的 `rebuild.txt`、用于比较的 `surface.bin`。优化前后使用同一存档和场景，分别保留输出并比较二进制；计时只覆盖对应函数，二进制导出不计入重建耗时。记录多个样本有助于排除编辑器波动。停止 Play 并确认完全退出后，恢复备份存档，避免自动保存留下测试进度。

仍有约 0.6 秒的完整重建开销；本次没有把它描述为无卡顿，也没有声称整体帧率提升。后续若仍有明显停顿，应继续测量草地重建、碰撞体烘焙与渲染线程，再决定是否拆分地形块。
